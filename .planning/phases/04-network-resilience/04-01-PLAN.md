  <action>
Create a Ktor HttpClient plugin for retry with exponential backoff.

Use Ktor 3.x createClientPlugin API:
```kotlin
val RetryPlugin = createClientPlugin("RetryPlugin", ::RetryPluginConfig) {
    // Configuration and implementation
}
```

RetryPluginConfig class with:
- retryPolicy: RetryPolicy = RetryPolicy.DEFAULT
- retryableStatusCodes: Set<HttpStatusCode> (default: 408, 429, 500, 502, 503, 504)
- shouldRetry: (HttpResponse) -> Boolean lambda for custom logic

Implementation requirements:
1. Wrap request in retry loop
2. On retryable failure (status code in set OR IOException), delay then retry
3. Use kotlinx.coroutines.delay() which respects cancellation (NET-05)
4. Check isActive before each retry to honor cancellation
5. Log retry attempts via platform Logger if available (optional - inject via config)
6. After max retries exhausted, return the last error response

Do NOT retry on:
- 4xx client errors (except 408, 429)
- CancellationException (rethrow immediately)
- Non-retryable custom conditions

Reference Ktor docs for createClientPlugin pattern. Avoid deprecated HttpSend.
