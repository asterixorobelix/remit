# Milestone v1.0: Template Enhancement

**Status:** ✅ SHIPPED 2026-01-16
**Phases:** 1-5
**Total Plans:** 11

## Overview

Transform the existing KMP template into a production-ready starter kit by adding iOS privacy compliance, modern build configuration, feature flags, resilient networking, and comprehensive documentation. Each phase delivers independent value while building toward the goal of "zero-to-app-store with minimal friction."

## Phases

### Phase 1: iOS Privacy Manifest

**Goal**: iOS app passes App Store privacy requirements
**Depends on**: Nothing (first phase)
**Requirements**: INFRA-01, INFRA-02
**Plans**: 1 plan

Plans:
- [x] 01-01: Create privacy manifest with Kotlin runtime API declarations

**Details:**
Created PrivacyInfo.xcprivacy with FileTimestamp (0A2A.1) and UserDefaults (CA92.1) declarations. Fixed pre-existing FirebaseConfigChecker iOS compilation blocker using expect/actual pattern.

### Phase 2: Build Configuration

**Goal**: Modernize build system and optimize iOS compilation
**Depends on**: Phase 1
**Requirements**: INFRA-03, INFRA-04, INFRA-05
**Plans**: 2 plans

Plans:
- [x] 02-01: Update Compose Multiplatform to 1.10.0
- [x] 02-02: Configure iOS architecture selection and Gradle compatibility

**Details:**
Updated Compose Multiplatform from 1.9.3 to 1.10.0. Verified iOS ARM64-only architecture configuration (iosArm64 + iosSimulatorArm64). Documented deprecation warnings for future maintenance.

### Phase 3: Feature Flags

**Goal**: Zero-config feature flags with optional Firebase Remote Config
**Depends on**: Phase 2
**Requirements**: FLAG-01, FLAG-02, FLAG-03, FLAG-04, FLAG-05
**Plans**: 1 plan

Plans:
- [x] 03-01: Create FeatureFlags interface, LocalFeatureFlags, DebugFeatureFlags, and Koin module

**Details:**
Created FeatureFlags interface with typed boolean properties, LocalFeatureFlags for zero-config operation, and DebugFeatureFlags decorator for runtime overrides. Registered via Koin DI.

### Phase 4: Network Resilience

**Goal**: Production-ready HTTP retry with exponential backoff
**Depends on**: Phase 2 (needs updated Ktor)
**Requirements**: NET-01, NET-02, NET-03, NET-04, NET-05
**Plans**: 2 plans

Plans:
- [x] 04-01: Create RetryPolicy and Result types
- [x] 04-02: Implement Ktor retry interceptor with jitter

**Details:**
Created RetryPolicy with exponential backoff calculation, NetworkResult sealed class for typed error handling, and RetryPlugin using Ktor 3.x createClientPlugin API. Added HttpClientConfig with configurable timeouts and NetworkModule for Koin DI.

### Phase 5: Documentation

**Goal**: Developer documentation for template users

## Milestone Summary

**Key Decisions:**

- Decision: Used reason code 0A2A.1 for FileTimestamp (Rationale: SDK wrapper usage by Compose Multiplatform)
- Decision: Used reason code CA92.1 for UserDefaults (Rationale: app-only preferences access)
- Decision: Keep materialIconsExtended at 1.7.3 (Rationale: independent versioning scheme from JetBrains)
- Decision: Boolean flags only (Rationale: deferred multi-type support for simplicity)
- Decision: Ktor 3.x createClientPlugin for retry (Rationale: modern API, deprecated HttpSend replaced)
- Decision: ignoreUnknownKeys=true (Rationale: forward API compatibility)
